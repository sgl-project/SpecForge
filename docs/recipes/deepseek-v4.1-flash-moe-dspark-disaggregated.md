# DeepSeek-V4.1-Flash DSpark disaggregated training

Fine-tunes DeepSeek-V4.1's own DSpark drafter, the `mtp.*` module the checkpoint
ships (`configs/deepseek-v4.1-flash-moe-dspark.json`: three V4.1 blocks with
single-pass mHC and a 128-expert MoE, 14.2B parameters), for
`deepseek-ai/DeepSeek-V4.1-Flash` on thinking-mode data regenerated by the
target. The recipe fits one 6-GPU B200 node: a TP4/EP4 capture server on
GPUs 0-3 and a two-rank trainer on GPUs 4-5. It was validated end to end:
capture, 30 optimizer steps from the official weights, export back to the
official layout.

The flow is the standard disaggregated setup
(`docs/basic_usage/disaggregated_training.md`); what is DeepSeek-V4.1-specific:

- **SGLang revision**: V4.1 needs SGLang 0.5.21 or later, and the capture plugin
  needs the forward-observer and deferred-response extension points that landed
  after the 0.5.23 release. The capture server therefore runs SGLang
  `c757c4bb7c55d1eb69fdb2bdc6e6fb8507acb7a0` with
  `plugins/sglang-spec-capture` installed; there is no source patch.
- **Capture hook**: `--speculative-algorithm DSPARK --enable-return-aux-hidden-states
  --return-aux-hidden-state-layer-ids 37 38 39` reaches the model's
  `set_dspark_layers_to_capture` hook, which reads the mHC stream averaged over
  its four copies at the inputs of layers 37-39, as the official drafter does.
- **Expert parallelism**: TP alone splits the 2304-wide experts into 288
  columns, which the fp4 MoE kernels reject (they need multiples of 128);
  `--ep-size 4` keeps the experts whole.
- **Memory**: 510 GB of fp4/fp8 weights on four 178 GB GPUs leave about 50 GB
  each. `--mem-fraction-static 0.80 --max-running-requests 4` keeps the MoE
  kernels' workspace for a 16k-token prefill; 0.85 runs out of memory there.
- **Chat encoding**: the checkpoint ships a Python encoder; the
  `deepseek-v4.1-thinking` template renders the regenerated rows with the
  vendored copy (`DeepSeekV41Parser`), `reasoning_content` inside `<think>`.
- **Mooncake**: the server, the trainer and `mooncake_master` must run the same
  `mooncake-transfer-engine` wheel; a mismatch fails every publication with
  `Batch RPC call failed: invalid rpc arg`.

## Warm start

```bash
python scripts/convert_deepseek_v41_dspark.py \
  --source deepseek-ai/DeepSeek-V4.1-Flash \
  --output outputs/deepseek-v4.1-flash-dspark-draft
```

This is the recipe's `draft_checkpoint_path`: the official `mtp.*` tensors
dequantized to bf16 (27 GB). The official routing biases are zero, which the
draft config keeps (`moe_router_bias_update_rate: 0`).

## Data

Regenerate the prompts with the target in thinking mode against a plain V4.1
server (`--reasoning-parser auto`):

```bash
python scripts/regenerate_train_data.py \
  --model deepseek-ai/DeepSeek-V4.1-Flash \
  --server-address localhost:31000 \
  --concurrency 192 --max-tokens 16384 --temperature 1.0 --reasoning save \
  --input-file-path prompts.jsonl \
  --output-file-path cache/dataset/deepseek-v4.1-flash-thinking-regen.jsonl \
  --resume
```

Rows whose reasoning runs past `--max-tokens` have no answer and land in the
`_error` file (about 8% at 16k tokens on a mixed math/code/chat pool).

## Capture server (GPUs 0-3)

The server environment, as the training package's CI builds it: torch 2.14.1
(cu130), `sglang @ git+https://github.com/sgl-project/sglang.git@c757c4bb7c55d1eb69fdb2bdc6e6fb8507acb7a0#subdirectory=python`
installed with `--no-build-isolation`, the Mooncake wheel the trainer uses,
then `pip install --no-deps plugins/sglang-spec-capture`.

```bash
mooncake_master \
  --enable_http_metadata_server=true \
  --http_metadata_server_host=0.0.0.0 \
  --rpc_port=35551 \
  --http_metadata_server_port=35880 \
  --metrics_port=35903 \
  --default_kv_lease_ttl=5m
```

```bash
export MOONCAKE_MASTER_SERVER_ADDR=127.0.0.1:35551
export MOONCAKE_METADATA_SERVER=http://127.0.0.1:35880/metadata
export MOONCAKE_LOCAL_HOSTNAME=127.0.0.1
export MOONCAKE_PROTOCOL=tcp
export MC_TRANSFER_TIMEOUT=300
export MOONCAKE_GLOBAL_SEGMENT_SIZE=$((200 << 30))
export MOONCAKE_LOCAL_BUFFER_SIZE=$((1 << 30))
export SPECFORGE_SPEC_CAPTURE=1
CUDA_VISIBLE_DEVICES=0,1,2,3 python -m sglang.launch_server \
  --host 0.0.0.0 \
  --port 30000 \
  --model-path deepseek-ai/DeepSeek-V4.1-Flash \
  --trust-remote-code \
  --skip-tokenizer-init \
  --tp-size 4 \
  --ep-size 4 \
  --mem-fraction-static 0.80 \
  --context-length 16896 \
  --max-running-requests 4 \
  --chunked-prefill-size -1 \
  --max-prefill-tokens 16896 \
  --speculative-algorithm DSPARK \
  --enable-return-aux-hidden-states \
  --return-aux-hidden-state-layer-ids 37 38 39 \
  --return-hidden-states-mode full
```

The log must show `SpecForge spec capture enabled (host publication,
writer=True)`. The first launch spends about 20 minutes compiling and
autotuning the fp4 MoE kernels; later launches reuse the cache.

## Trainer (GPUs 4-5)

```bash
CUDA_VISIBLE_DEVICES=4,5 specforge train \
  -c examples/configs/online/disaggregated/external/deepseek-v4.1-flash-moe-dspark.yaml
```

Supply `HF_TOKEN` and `WANDB_API_KEY` through the environment, not YAML. On a
host whose Hugging Face caches point at a read-only share, set
`HF_DATASETS_CACHE` and `HF_MODULES_CACHE` to a writable directory. Measured on
the validation run (global batch 8, two ranks): about 45 s per optimizer step,
132 GB per trainer GPU with FULL_SHARD and the optimizer offloaded, no wait on
capture.

## Export

```bash
specforge export --to hf \
  --checkpoint outputs/deepseek-v4.1-flash-moe-dspark-disaggregated/<run>-step<N> \
  --draft-config configs/deepseek-v4.1-flash-moe-dspark.json \
  --output-dir outputs/<run>-hf \
  --embedding-source deepseek-ai/DeepSeek-V4.1-Flash --embedding-key embed.weight
python scripts/convert_deepseek_v41_dspark.py --to-official \
  --source outputs/<run>-hf --output outputs/<run>-official \
  --official-config /path/to/DeepSeek-V4.1-Flash/config.json
```

The official directory holds the 1,224 unquantized `mtp.*` tensors (the
image-token routing bias written as a copy of the text one) and the official
config without its quantization fields.

## Fresh attempts

Delete the run's `outputs/` directory and, whenever a capture server was
restarted, use a fresh Mooncake namespace (restart `mooncake_master`, or
override `deployment.disaggregated.store_id=<unique-attempt-id>`): the
producer dedups against keys already registered in the master, and keys whose
replicas lived in a dead server's segment poison the consumer with
`get_into failed` errors.
